# Motion review

Done with the Emil Kowalski skills (`emilkowalski/skill`): find-animation-opportunities
to choose, animate and animate-expo to build, review-animations standards to check.
Every candidate went through four gates: how often it is seen, what it is for,
whether it fits the speed budget, and whether motion helps or hurts the task.

## Frequency map

| Surface | Seen | Verdict |
|---|---|---|
| Marketing home and articles | Once or twice per visitor | Eligible, kept restrained |
| Early-access form | Once | Eligible for feedback only |
| Dashboard lead queue, tables, filters | Dozens of times a day | Near-imperceptible colour change only |
| Dashboard navigation and tab bar | Hundreds of times a day | No animation |
| Dashboard setup checklist, empty states | First run | Eligible, one state transition |

## What was added

| # | Where | Purpose | Motion |
|---|---|---|---|
| 1 | Every landing button | Feedback | `:active { transform: scale(0.97) }`, 120ms, `cubic-bezier(0.23, 1, 0.32, 1)` |
| 2 | Arrow in the primary buttons | Feedback (hover) | Nudges 2px right and 2px up on a 640ms spring (`{ duration: 0.5, bounce: 0.15 }` sampled into `linear()`), returns in 200ms ease-out. Only on hover-capable pointers and only without reduced motion |
| 3 | Hero ledger | Explanation, seen once per visit | Six rows rise 6px and fade in, 360ms ease-out, 70ms apart. The booked row turns green last, 400ms after the sequence. Reduced motion: fade only, 60ms apart. Text is real and readable throughout |
| 4 | Moving between pages | Preventing a jarring change | 160ms crossfade through `@view-transition`, header pinned with its own `view-transition-name`. Off under reduced motion |
| 5 | All hover colour changes | State indication | Gated behind `(hover: hover) and (pointer: fine)` so a tap never leaves a link lit |
| 6 | Tap highlight on touch | Feedback | System flash removed; the press scale replaces it |
| 7 | Dashboard queue rows, table rows, filter chips, checklist rows, disclosure headers | State indication | Background and border colour, 120ms, plain `ease`, hover on mouse pointers only. Nothing moves |
| 8 | Dashboard buttons | Feedback | Hover now matches the existing press colour; the existing 3% press scale is unchanged |
| 9 | Dashboard checklist circle | State indication | Fill and border change over 120ms when a step completes. Nothing plays on first render |

The early-access status message already rose in over 200ms with the strong
ease-out and respected reduced motion. It was left alone.

## Rejected, with the gate that killed each

| Candidate | Rejected because |
|---|---|
| Scroll-triggered reveals on every section | Frequency is low but the content is text people read; making it wait for an animation is a cost with no purpose |
| Counting up "42 hours" and "21x" | Function: figures the reader is trying to read should not move |
| Hover lift on step, team and FAQ rows | They are not clickable; a hover affordance would imply they are |
| Sliding or fading tab and nav changes in the dashboard | 100+ a day. Peers do not slide |
| Entrance animation on dashboard queue rows | Dozens of times a day, and it delays reading the most urgent lead |
| Hold-to-confirm on destructive actions | Not asked for and no destructive action sits on the screens reviewed |
| Table-of-contents scroll-spy | A feature, not motion; out of scope here |
| Animated focus ring | Keyboard-initiated. Focus stays instant |

## Review against the standards

| Before | After | Why |
| --- | --- | --- |
| Hero buttons pressed with `translateY(1px)` | `scale(0.97)` at 120ms | A scale takes the label and icon with it and reads as physical |
| Hover rules applied on touch devices | Every hover rule inside `@media (hover: hover) and (pointer: fine)` | Touch fires hover on tap and leaves the element stuck |
| Arrow nudge would sit outside reduced-motion handling | Gated on `no-preference` as well as hover | Reduced motion removes movement and keeps colour |
| Reduced-motion reset written outside the hover gate | Rule moved into one gated block, override deleted | One place to read, nothing to keep in sync |
| Dashboard rows, filters and checklist items changed colour instantly | 120ms `ease` on background, border and text colour | A snap reads as a glitch; anything longer would slow a screen used all day |
| Dashboard hover state missing | Hover reads `hovered`, which React Native Web sets for mouse only | A tap cannot leave a row stuck |
| Page changes flashed white between documents | 160ms crossfade, header pinned | The header is the one thing that must not move |
| `transition: all`, `ease-in`, `scale(0)` | None present; a test fails the build if one appears | Cheap to regress, so it is guarded |

## Checked in a browser (17 checks, all passing)

Run with Playwright at 1440 and 390 wide. The ledger runs eight animations on
load and none at rest, and every row ends fully visible. Hover moves the arrow
by exactly (2, -2). Press scales the button to 0.97 and release returns it to
rest. No `transition: all`. Reduced motion swaps the ledger to a fade, stops the
arrow, stops the press scale and turns smooth scrolling off. A touch device does
not match the hover query and a tap leaves no stuck nudge. The header keeps its
own view-transition name and the page change navigates correctly. The page
loads without script errors.

`tests/landing-motion.test.ts` keeps the static rules: no `transition: all`, no
`ease-in`, no `scale(0)`, hover only inside the gate, a reduced-motion
alternative for movement, UI transitions under 300ms unless they ride the spring,
and a 3% press.

## What code cannot tell you

- **Feel.** Whether the 640ms spring reads as alive or as slow, and whether the
  ledger's 70ms stagger reads as a sequence, need a person watching. Play both
  at 3x in DevTools (Animations panel) and look again tomorrow.
- **Dashboard on a phone.** The colour changes are web-only by design (native has
  no hover, and its press feedback already exists). Judge them on a release build
  on the slowest device you support, not in Expo Go.
- **Safari.** `@view-transition` is progressive: browsers without it simply
  navigate, which is the previous behaviour.

## Verdict

The marketing site needed a little motion and the dashboard needed almost none.
The dashboard already had a complete system (press scale, edge-matched
entrances and exits, reduced-motion twins); it was missing only a visible
response on the rows people touch most, and that response is a colour change, not
movement. The highest-leverage addition is the hero ledger, because it is the
one place where motion carries an argument: thirty seconds, in order.
