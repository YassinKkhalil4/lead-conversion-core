# Risks

| Risk | Severity | Status | Mitigation |
|---|---:|---|---|
| Evidence archive contains credential categories and PII-bearing artifacts | Critical | open | Exclude from repo, document rotation, do not print values. |
| Legacy `/v1/turn` active route sends Meta messages inside a DB transaction | Critical | mitigated_locally | The route is disabled by default behind `ACTIVE_TURN_COMPAT_ENABLED`; new direct Meta ingress uses durable inbox/outbox. |
| Legacy `/v1/turn` active route can fall back to legacy after definite Meta rejection | High | mitigated_locally | The route is disabled by default behind `ACTIVE_TURN_COMPAT_ENABLED`; new edge-owned durable inbound processing ignores legacy-owned conversations and enqueues outbound effects transactionally. |
| Legacy `edge_outbox` compatibility worker can retry forever | High | mitigated_locally | Legacy `edge_outbox` now has a terminal `dead_lettered` status after bounded retries; durable runtime outbox already has leases, bounded attempts, and dead letters. |
| Provider event ID reuse with changed payload can suppress business processing or lose collision evidence | High | mitigated_locally | Durable inbox receipt now accepts duplicate provider dedupe keys only when event type, external event ID, aggregate identity, and payload hash match the original inbox row; changed-payload collisions fail closed and preserve the original receipt/event. |
| Durable idempotency keys can hide changed external effects or schedules | High | mitigated_locally | Durable outbox enqueue and scheduled-job creation now reuse existing rows only when persisted semantics match the requested command or job; a reused key with changed payload, destination, schedule, recurrence, or attempt policy fails closed as a collision. |
| Webhook verification tokens can appear in request URLs | High | mitigated_locally | Request logging redacts sensitive query parameters, including Meta `hub.verify_token`, and authentication/signature headers before emission. |
| Deployment or operator verification can expose secrets through process arguments or child environments | High | mitigated_locally | `scripts/verify-deployment.sh` and `scripts/shadow-sequence.sh` parse one-line env files without `source` or `eval`, reject duplicate keys and decoded control characters, keep values shell-local, chmod parsed assignment temp files private, and pass edge shared-secret and internal-secret headers through private temporary files; Meta challenge, signed POST, and unsigned POST verification use private curl config files. The deployment verifier rejects duplicate, empty, unknown, or control-character-bearing arguments before loading env, and `scripts/shadow-sequence.sh` rejects all arguments before reading `.env`. |
| Backup and restore scripts can expose password-bearing PostgreSQL URLs through process arguments, ignore typoed operator arguments, overwrite evidence, or restore corrupted artifacts | High | mitigated_locally | Backup, restore, and restore-verification scripts reject positional/flag arguments before reading required secret-bearing env, convert database URLs into private temporary libpq service files, unset the original URL variables, and invoke PostgreSQL tools with non-secret service names; backup creation locks timestamped encrypted dump/checksum paths, refuses existing outputs, removes partial encrypted output on incomplete backup, and restore verifies the encrypted dump SHA-256 checksum before decryption unless the operator explicitly opts into unchecked restore. Docker dump inspect/restore-smoke wrappers also reject all arguments before reading `DUMP_PATH` or invoking Docker. |
| Calendar reconciliation operator commands can mutate durable state from ambiguous CLI input | High | mitigated_locally | `npm run calendar:reconcile` now rejects unknown commands, unknown or duplicate flags, non-canonical list limits, malformed outbox UUIDs, empty provider IDs/reasons/operator IDs, and control characters before constructing the reconciliation service or querying PostgreSQL. |
| Configuration publish or rollback can mutate active configuration from ambiguous CLI input | High | mitigated_locally | `npm run config` now accepts only closed commands and command-specific flags, rejects duplicate flags, rejects simultaneous seed/Airtable source selection, requires rollback version keys, and rejects empty or control-character-bearing operator values before constructing the configuration service or querying PostgreSQL. |
| Seed bootstrap can create legacy-only configuration authority or ignore typoed operator arguments | High | mitigated_locally | `npm run seed` now publishes the seed source through `VersionedConfigService`, creates or reuses immutable `configuration.versions` and `configuration.active_versions` rows, maintains `edge_config_snapshots` only through the versioned compatibility update, and rejects all unknown or control-character-bearing operator arguments before querying PostgreSQL. |
| Legacy config import or Airtable sync can bypass immutable versioned configuration authority | High | mitigated_locally | `/internal/config/import`, `/internal/config/sync`, and `npm run sync-config` are disabled by default behind explicit compatibility flags; live Airtable sync additionally requires `AIRTABLE_TOKEN`, and the `sync-config` CLI rejects ambiguous or unsafe operator arguments before service use. |
| Airtable import or reconciliation can write migration evidence from ambiguous CLI input | High | mitigated_locally | `npm run import:airtable` now requires explicit `--input=<dir>` and accepts only bare `--apply`; `npm run reconcile:airtable` accepts only optional `--import-run-id=<uuid>` and bare `--record-results`; both reject unknown, duplicate, empty, malformed, or control-character-bearing arguments before source-file loads or PostgreSQL queries. |
| Local env generation can expose newly generated credentials through child-process arguments or ignore typoed operator input | High | mitigated_locally | `scripts/generate-env.sh` rejects all arguments before checking or creating `.env`, writes generated database and service secrets to private temporary files, unsets the shell variables, and passes only file paths to Python while rendering `.env`. |
| Local baseline verification helpers can produce evidence while ignoring typoed inputs | Medium | mitigated_locally | `scripts/ops/scan-tracked-artifacts.sh`, `scripts/smoke-engine.ts`, `scripts/smoke-integration.ts`, and `scripts/simulate-conversation.ts` reject all operator arguments before producing scan, smoke, integration, or simulation output; `scripts/backup/sha256-file.sh` accepts exactly one readable non-control-character path. |
| External integration flags can be enabled without required credentials | High | mitigated_locally | Environment validation now rejects enabled legacy outbox, direct Meta webhook/send, active-turn compatibility, and Google Calendar modes unless their required target URLs, secrets, access tokens, or phone IDs are configured. |
| Migrator can ignore typoed operator arguments before mutating schema | High | mitigated_locally | `npm run migrate` and `npm run migrate:prod` now reject all unknown or control-character-bearing arguments before importing database runtime modules or opening PostgreSQL. |
| API and worker both run migrations at startup | High | mitigated_locally | One-shot migrator added; local concurrent migration test passed. |
| No complete Airtable export is present | High | owner_action_pending | Build importer/dry-run/reconciliation and await owner export. |
| Local `pg_restore` cannot inspect supplied dumps | Medium | workaround_available | Use PostgreSQL 16+ Docker tooling for dump metadata and restore tests. |
| No lockfile in supplied canonical source | Medium | mitigated_locally | `package-lock.json` generated; `npm ci` verified. |
| Docker daemon unavailable in local environment | Medium | open | Static Compose validation passed; image build/run and Docker-based dump inspection require daemon access. |
